Asynchronous execution in JavaScript means the code doesn’t wait for a long-running task to finish.
Instead, JavaScript moves on to the next line, and the long task finishes in the background.
When the task is done, it notifies JavaScript to continue using callbacks, promises, or async/await.

Why do we need asynchronous execution?

JavaScript runs on a single thread (one line of code at a time).
If it waited for slow operations like:

API calls

Reading files

Database queries

Timers (setTimeout)

…your entire page/app would freeze.

Asynchronous execution prevents that freeze.

Synchronous (Blocking)
The next line waits until the current line finishes.

console.log("Start");

function syncTask() {
  for (let i = 0; i < 5000000000; i++) {} // heavy loop
}

syncTask();
console.log("End");

Output:
Start
(huge delay…)
End


Asynchronous (Non-Blocking)
The heavy work happens in the background.

console.log("Start");

setTimeout(() => {
  console.log("Async task done");
}, 2000);

console.log("End");

Output:
Start
End
Async task done   (after 2 seconds)

JavaScript does not wait for setTimeout.

 How does JavaScript handle async code?
Using:


Callbacks → old style


Promises → modern


async / await → easiest
